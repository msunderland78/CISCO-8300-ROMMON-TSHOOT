This confirms the session setup; it does not replace a fresh cable loopback/known-good-device comparison.

The AI-assisted [receive-only capture helper](../../scripts/c8300_console_capture.py) uses Python 3 standard-library POSIX termios/select/fcntl. It has no hardware side effects on import/help. Explicit live mode opens the supplied device exclusively, sets 8N1 without flow control, and records original received bytes privately. It sends **no bytes and no BREAK**, including on receiving a banner. Stdin JSON controls can report status, mark owner observations, change between 9600/115200, or close. stdout contains timestamped metadata/counts/hashes, not raw console output.

Executed after physical confirmation:

```sh
python3 scripts/c8300_console_capture.py --live --port /dev/cu.usbserial-AL00F7EQ --baud 9600 --confirmed-pid C8300-1N1S-4T2X
```

The first software attempt stopped before capture-ready because lsof reports exit 1 when the unused tty alias has no descriptor even when the opened cu alias is owned only by the helper. That behavior was reproduced; the post-open check now checks the actual opened node after TIOCEXCL, while the pre-open check still checks both aliases. Both attempts are retained privately. This was a capture-software preflight issue, not a measured router fault.
